# Cambium Glossary — Naming Map

This is the human + agent bridge for Cambium vocabulary. `architecture.md` v2 is
authoritative; `system-design.md` v0.1 supplies history, and `agents.md` makes the
repository vocabulary norm explicit.

**Naming philosophy:** FB4 #1 rejected renaming the Latin module names; the names stay, and this glossary is the bridge between those names and plain English.

I2.1–I2.7 are separate entries so an agent can look up one invariant without
unpacking a compound definition. Config and wire examples usually spell provider
tiers in lowercase (`fast`, `balanced`, `strong`, `reasoning`); the glossary uses
uppercase when naming the tier family.

| Term | Meaning | Where it lives | Synonyms / legacy names |
|---|---|---|---|
| **Custos (M4)** | The deterministic supervisor. It owns worker lifecycle, watchdogs, restart policy, budgets, gates, event emission, and worktree recovery; it never calls an LLM. | `docs/architecture/architecture.md` §§2, 4, 7; `src/cambium/supervisor.py` (vertical-slice and multi-worker runtime) | Supervisor; deterministic layer; v0.1 `Supervisor` class |
| **Opifex (M5)** | The worker runtime process. It executes one node's coding loop and tools, emits heartbeats and checkpoints, and returns a result and exit message from its isolated worktree. | `docs/architecture/architecture.md` §§2, 4, 7.6; `src/cambium/worker.py` (`python -m cambium.worker`) | Worker; worker runtime; v0.1 `WorkerAgent` / `worker.py` |
| **Nuntius (M1)** | The IPC framing layer. It carries newline-delimited JSON over stdio, correlates RPC messages with `request_id`, and does not apply workflow policy. | `docs/architecture/architecture.md` §5; `src/cambium/ipc.py` | IPC; protocol; messenger; v0.1 newline-delimited JSON |
| **Unio (M7)** | The serialized merge sequencer. It rebases or stages a worker branch in a throwaway worktree, runs the final test gate, and atomically fast-forwards `refs/heads/main`; it is the only Cambium writer to `main`. | `docs/architecture/architecture.md` §§4, 7.8; `src/cambium/merge.py` | Merge; merge sequencer; v0.1 `MergeSequencer` |
| **Surculus (M3)** | Worktree management: create, recover, prune, and list task worktrees, including lock cleanup, reset/clean, and generation updates. There is no standalone `surculus.py` in the current surface; the plumbing is split between the supervisor and merge code. | `docs/architecture/architecture.md` §§4, 7.5; worktree portions of `src/cambium/supervisor.py` and `src/cambium/merge.py` | Worktree manager; worktree management; v0.1 `WorktreeManager` |
| **Diffundo (M2)** | The stateless multi-provider LLM router. It filters by tier and capabilities, cascades by provider priority, applies cooldowns and token buckets, and has no local production response cache. | `docs/architecture/architecture.md` §§4, 8.1, 9; `src/cambium/diffundo.py` when merged; provider loading in `src/cambium/provider_config.py` | LLM router; multi-provider access; **FanOut**; v0.1 `FanOut` |
| **Architectus (M6)** | The orchestrator and DAG executor. It plans, decomposes, validates, schedules, composes context, steers NodeSessions, aggregates envelopes, evaluates results, and replans; it sends typed actions to Custos instead of spawning processes or mutating git directly. | `docs/architecture/architecture.md` §§2, 4, 3.7; current entry point `src/cambium/orchestrator.py`; `src/cambium/architectus.py` when merged; `docs/research/architectus-design.md` §1.2 | Orchestrator; DAG executor; RLM task-tree orchestrator; v0.1 `Orchestrator` |
| **Ascensus (M9)** | The offline evaluation and optimization harness. It runs module metrics over datasets and canaries, compares baselines, and stores optimization artifacts; it is not on the production hot path. | `docs/architecture/architecture.md` §§4, 10, 17; `src/cambium/bench.py`; eval-only cache in `src/cambium/eval_cache.py` | Eval harness; optimization harness; DSPy optimization; v0.1 optimization flywheel / SIMBA-GEPA harness |
| **Septum (M8)** | The historical sandbox wrapper. It is **removed from v2 scope**; current containment is worktree isolation, permission allowlists, and approval gates, with deployment isolation owned by the host. | `docs/architecture/architecture.md` §4 M8 and §7.2; historical design in `docs/architecture/system-design.md` §M8; evidence in `docs/research/sandbox-options.md` | Sandbox; sandbox wrapper; M8; legacy namespace wrapper / firejail |
| **Janus (M10)** | The external interface: the unified CLI and optional TUI. The TUI is a read-only view over `Session.events()` and never becomes a second control plane. | `docs/architecture/architecture.md` §§4, 15; `src/cambium/cli.py`; optional `cambium.tui` policy | Interface; CLI/TUI; view; v0.1 CLI / TUI |
| **Task tree** | An explicit per-session DAG of task nodes, with one root and parent/child delegation. The scheduler dispatches ready nodes in waves while deterministic validation enforces the tree bounds before work starts. | `docs/architecture/architecture.md` §3.7 and I2.1–I2.5; `src/cambium/tasktree.py`; `docs/research/architectus-design.md` §2 | `TaskTree`; task DAG; v0.1 flat subtask list; `depends_on` is the current parent link (`requires` is a legacy description) |
| **NodeSession** | The checkpointed, reloadable sub-session owned by one task-tree node, with `session_id == task_id` and its own conversation history. A parent can steer a live node, but the node sends only its result envelope upward. | `docs/architecture/architecture.md` §§3.7, 5.2, 6.6; `src/cambium/worker.py`; `docs/research/architectus-design.md` §0 | Node sub-session; child session; task session; v0.1 worker task |
| **Generation / fencing** | A monotonically increasing per-task spawn number that is sent in `init`, echoed by worker messages, and written to `.cambium/generation` in the worktree. A stale worker that sees a mismatch must exit before a git or state write, preventing split-brain work. | `docs/architecture/architecture.md` §7.3; `src/cambium/fencing.py`; recovery and spawn paths in `src/cambium/supervisor.py` | Fencing token; generation counter; stale-worker fence; split-brain guard |
| **Result envelope** | The strict child-to-parent terminal payload, distinct from the session-level `Result`. It carries the parent link, capped `unified_diff`, `diff_truncated`, summary, metrics, commits, changed files, and status—never scratchpad, chain-of-thought, or trajectory. | `docs/architecture/architecture.md` §§3.4, 3.7 I2.7, 5.2; `src/cambium/tasktree.py` `upward_result()`; `src/cambium/worker.py` | Upward envelope; child result; `result_envelope`; v0.1 `result` message |
| **I2.1 — Single root** | A session has exactly one root node. Every non-root node has exactly one `parent_task_id`, so the parent link is unambiguous before dispatch. | `docs/architecture/architecture.md` §3.7 I2.1; `src/cambium/tasktree.py` `build_tree()` | One-root rule; root invariant |
| **I2.2 — No cycles** | The decomposition graph is acyclic, has no self-loops, and forbids multi-parent nodes in v2. `build_tree()` and topological ordering detect a cycle before dispatch so no task can remain pending forever. | `docs/architecture/architecture.md` §3.7 I2.2; `src/cambium/tasktree.py` `_find_cycle()` and `topological_order()`; `docs/research/feedback-4-assessment.md` claim 6 | Cycle detection; acyclic plan; D2 DAG invariant |
| **I2.3 — Depth and width bounds** | `max_depth` bounds nesting and `max_width` bounds fan-out/concurrent worker admission. The task-tree builder checks structural depth and per-parent fan-out; Custos enforces the session-wide dispatch cap. | `docs/architecture/architecture.md` §3.7 I2.3; `src/cambium/tasktree.py` `MAX_DEPTH`/`MAX_WIDTH`; `src/cambium/supervisor.py` | Tree bounds; fan-out limit; concurrency cap |
| **I2.4 — Context composition** | A node sees its bounded own session log, its parent's summary, and subtree result envelopes. It never reads a sibling's raw session, so sibling communication is parent-mediated. | `docs/architecture/architecture.md` §3.7 I2.4 and §6.6; `docs/research/architectus-design.md` §§3.1–3.5 | Context composition; sibling isolation; bounded context rule |
| **I2.5 — Tree-level completion** | A node is terminal only after its own work is complete and every child has returned an envelope recursively. The root's terminal envelope becomes the session result. | `docs/architecture/architecture.md` §3.7 I2.5 and §7.1; `docs/research/architectus-design.md` §2.3 | Recursive completion; subtree completion; root completion rule |
| **I2.6 — Append-only session logs** | Node history is immutable. Steering and new observations append turns rather than editing old records, preserving replay and reload semantics. | `docs/architecture/architecture.md` §3.7 I2.6 and §6.6; `docs/research/architectus-design.md` §3.2 | Append-only history; conversation log; immutable session history |
| **I2.7 — Information hiding** | Upward messages are structurally restricted to the result-envelope keys. Scratchpads, chain-of-thought, reasoning traces, and trajectories do not cross the child-to-parent boundary. | `docs/architecture/architecture.md` §3.7 I2.7 and §5.2; `src/cambium/tasktree.py` `_ENVELOPE_KEYS`; Nuntius/Custos validation | Envelope-only upward flow; scratchpad isolation; information-hiding invariant |
| **Tier — FAST / BALANCED / STRONG / REASONING** | A provider capability class used as Diffundo's primary routing key; values are normally lowercase in config and calls. A request tries eligible providers in priority order within the tier, while an exact model is a deliberate explicit pin. | `docs/architecture/architecture.md` §§9.1–9.3; `src/cambium/provider_config.py`; `src/cambium/diffundo.py` when merged; `docs/research/cascade-design.md` §3.2 | Provider tier; capability tier; model tier; v0.1 model preference / provider priority (not an equivalent) |
| **Circuit breaker states** | Provider health states are `UNKNOWN`, `HEALTHY`, `COOLDOWN`, `OPEN`, `HALF_OPEN`, and terminal `DISABLED`. Architecture v2 specifies cooldown; the sliding-window breaker and its full state machine are the documented cascade design extension, with `OPEN` excluded and `HALF_OPEN` admitting one probe. | `docs/architecture/architecture.md` §9.1–9.2; `docs/research/cascade-design.md` §§2.3–2.4; Diffundo implementation when merged | Provider health; breaker; outage circuit; cooldown state |
| **Token bucket** | A per-provider throughput limiter refilled at `rpm`. An empty bucket marks the provider `RATE_LIMITED` and removes it through the same selection filter as cooldown; the bucket limits throughput, while cooldown limits repeated failures. | `docs/architecture/architecture.md` §9.1–9.2 (D8f); `docs/research/cascade-design.md` §§1.1, 2.3; Diffundo implementation when merged | RPM limiter; rate bucket; throughput bucket; v0.1 `rate_limit_remaining` |
| **Gate** | A deterministic verification command that defines whether work is done. Result receipt enters `GATING`; a pass reaches `DONE`, while a failure sends evidence back for bounded steering retries, and Unio's merge-time test is the final gate. | `docs/architecture/architecture.md` §§7.1, 7.8, 7.9; `src/cambium/supervisor.py` `_run_gate()`; `src/cambium/merge.py` | Test gate; verification gate; D4 gate; gate verdict |
| **DLQ** | The durable dead-letter queue stores failed supervisor records for later analysis, not automatic retry. Records are atomically written and fsynced under `.cambium/dlq`, with a bounded keep-newest policy. | `src/cambium/dlq.py`; session-state boundary in `docs/architecture/architecture.md` §16.2 | Dead-letter queue; dead-letter records; failed-record queue; not the restart queue |
| **Blackboard / `shared.db`** | The adopted cross-cutting-task design is a separate SQLite-WAL shared-facts store under `.cambium/sessions/shared.db`. Architectus is its single writer; workers read the `_shared` segment and submit proposals, which are validated and merged at wave boundaries, while ordinary tasks keep I2.4 isolation. | `docs/research/architectus-design.md` §3.6; planned layout in `docs/architecture/architecture.md` §16.2; implementation is a v2.1 design item | Blackboard; `_shared` context segment; shared context store; cross-cutting context; not `conversations.db` |
| **`include_diff`** | A per-task payload flag for upward envelopes. The default includes the capped `unified_diff`; `include_diff: false` omits that field for higher planning/routing tiers but retains `diff_truncated` and `files_changed`, with the diff available on demand for `merge_failed` resolution. | `docs/research/feedback-4-assessment.md` claims 7 and 21; `docs/research/architectus-design.md` §§0.3, 3.7; default envelope in `src/cambium/tasktree.py` | Diff inclusion flag; diff payload switch; unified-diff opt-out |
| **Canary** | A frozen trap case or assertion designed to expose reward hacking and metric regressions. A canary failure rejects an optimization/refinement, and in the coding metric it can zero the overall score. | `docs/architecture/architecture.md` §§10, 17.4; `docs/architecture/module-template/dataset-format.md` §6; `src/cambium/bench.py` `CANARY_TAXONOMY` | Canary suite; trap assertion; promotion gate; anti-reward-hacking case |
| **Dataset splits — train / eval / canaries** | `train` is the optimization input, `eval` is the frozen held-out quality gate, and `canaries` are the frozen trap suite with a 100% pass requirement. v2 may use one `<name>_pairs.jsonl` with inline canary markers; the three-file split is the v2.1 target and is consumed by the bench harness. | `docs/architecture/architecture.md` §§10, 17.3–17.4; `docs/architecture/module-template/dataset-format.md`; `src/cambium/bench.py` `SPLITS`; `src/cambium/modules/<name>/datasets/` | Trainset; held-out eval; canary suite; v0.1 combined trajectory/dataset set |
| **DSPy seam** | The stable replacement boundary for a decision module: `Module.decide()` remains the pure caller-facing operation while a DSPy program can replace the rule engine behind it. Callers, datasets, and metrics stay unchanged, and DSPy remains optional/lazy rather than a deterministic-layer dependency. | `docs/architecture/architecture.md` §§4, 17; `agents.md` §7; `src/cambium/modules/base.py`; `src/cambium/modules/example/decide.py`; `docs/architecture/module-template/example-spec.md` §5.1 | Engine-swap seam; DSPy adapter boundary; decision-program seam |
| **`.cambium/` session dir** | The dotted directory `${session_dir}/.cambium/` is Cambium-owned state; the host owns the parent session directory. It contains the event store and mirror, logs, result/status files, worktrees, checkpoints, per-node sessions, quarantine, and optimized artifacts, with no implicit global session state. | `docs/architecture/architecture.md` §16.2; `src/cambium/supervisor.py`, `src/cambium/store.py`, and `src/cambium/fencing.py` | Session state directory; hidden session directory; per-session Cambium state; legacy bare `cambium/` path is not canonical |
| **Provider prefix caching** | D1 permits provider-side exact-prefix KV caching only; it caches prompt-prefix computation, not a response, so changed content misses rather than serving stale output. Put byte-stable system instructions, guidelines, and tool definitions at the top of the prompt and dynamic task/repo content at the bottom; never put timestamps or request IDs in the static prefix. | `docs/architecture/architecture.md` §§8.1, 9.3; `agents.md` §8; `docs/research/architectus-design.md` §§3.1–3.2 | Prompt prefix caching; exact-prefix KV caching; provider-side caching; legacy local LLM response cache (removed) |
