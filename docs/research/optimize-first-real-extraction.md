**Status:** review queue only; optimization was intentionally not run.

Four had the OpenCode `session`/`project`/`message`/`part` schema and contained

| --- | ---: | --- |

| `opencode-instance2.db` | 1 | 2026-08-14..2026-08-14 |
| `opencode-update-upstream.db` | 1 | 2026-08-10..2026-08-10 |
| `opencode.db` | 174 | 2026-08-14..2026-08-20 |

`~/.config/opencode/` contained one `openai-compact/checkpoints.db` with a
`checkpoints` table, not an OpenCode transcript store. The pi store contained
639 JSONL session files in 527 project directories at the time of discovery;
the named Cambium and polymarket project directories contained 28 and 47
sessions respectively. The current extractor is the OpenCode SQLite adapter,
so pi JSONL files were counted but not copied or fed into this queue.

## Extraction

The queue was produced with the installed CLI path and explicit multi-repo,
multi-day bounds:

```sh
PYTHONPATH=src python -m cambium optimize extract \
  --session-dir ~/.local/share/opencode \
  --repo cambium \
  --repo polymarket-arbitrage \
  --from 2026-08-08T00:00:00Z \
  --to 2026-08-23T23:59:59Z \
  --output artifacts/optimization/first-real-extraction/review_queue.jsonl \
  --review-gate
```

The storage-directory adapter now ignores auxiliary SQLite files that do not
have the OpenCode session schema. The four session databases were read
read-only. The run selected 2,604 sessions, found 112 explicit decision /
rationale records, retained 112 safety-clean records, removed 89 duplicate
records, and emitted 23 unique candidates. There were zero conflicts,
exclusions, or unsafe records. All 23 emitted records came from `cambium`;
the polymarket filter produced no explicit candidate, which is a coverage
finding rather than an invented cross-repository sample.
