## Extraction

The queue was produced with the installed CLI path and explicit multi-repo,
multi-day bounds:

```sh
PYTHONPATH=src python -m cambium optimize extract \
  --session-dir ~/.local/share/opencode \
  --repo cambium \
  --repo polymarket-arbitrage \
  --from 2026-08-08T00:00:00Z \
  --to 2026-08-23T23:59:59Z \
  --output artifacts/optimization/first-real-extraction/review_queue.jsonl \
  --review-gate
```

The storage-directory adapter now ignores auxiliary SQLite files that do not
have the OpenCode session schema. The four session databases were read
read-only. The run selected 2,604 sessions, found 112 explicit decision /
rationale records, retained 112 safety-clean records, removed 89 duplicate
records, and emitted 23 unique candidates. There were zero conflicts,
exclusions, or unsafe records. All 23 emitted records came from `cambium`;
the polymarket filter produced no explicit candidate, which is a coverage
finding rather than an invented cross-repository sample.

### Sampling trajectory

Sampling used seed `20260824`. After the all-record schema, redaction,
truncation, non-triviality, reason-consistency, and normalized-task checks, 91
pi records remained in the initial review pool. The 60-record stratified sample
used quotas of 21 workstream, 3 file-surface, 22 clause, 1 observed-plus-task,
and 13 observed-only records. Deep grading accepted 30/60 (50.0%), below the
85% auto-promotion bar.

The gate was tightened to require a bounded task-level multi-workstream signal
(substantive actions, multiple file surfaces, or at least three explicit
items), while rejecting outcome-only provenance, meta/orchestration prompts,
and single-scope finalization tasks. That left 42 pi survivors; all 42 were
reviewed individually, with 32/42 accepted (76.2%) and 10 rejected. Because
neither trajectory reached 85%, no unreviewed pi remainder was promoted
programmatically; the 32 retained pi records are the manually accepted set.
