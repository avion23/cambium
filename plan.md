## 6. Cache, byte exactness, Codex, and child compatibility

### Byte exactness is mandatory

Provider prompt caches are exact-prefix and content-addressed. Byte equality is
a real cache requirement, not an optional optimization. Keep all of these
checks:

- `worker._resolve_fork_prefix` at `src/cambium/worker.py:1873-1953` validates
  descriptor fields, checkpoint hashes, `prompt_prefix_bytes`, the immutable
  base message list, and prompt structure. Any mismatch returns a skip reason
  and uses the legacy path.
- `diffundo.prompt_prefix_bytes` at `src/cambium/diffundo.py:388-404` measures
  the UTF-8 byte length of the leading system message. It is not a token
  approximation and does not prove a hit.
- The structural hard gate in
  `docs/research/cache-first-context-reuse-plan.md:597-605` requires 100%
  prefix byte equality for every fork/resume first turn. Keep it.

Do not propose removing equality, hashes, `validate_prompt_structure`, or the
stable provider/model/tool boundary. A provider miss is a normal observation;
it must not cause a fabricated prefix or an unsafe fallback. Deterministic
rolling compaction may change the mutable suffix only after its existing
publication and epoch rules; it must not mutate the stable head.

### Codex is structurally supported but telemetry-reporting-only

“Reporting-only” does **not** mean “remove Codex” or “disable fork/resume.” The
Codex structural path can still construct, validate, and run context forks and
resumes when the same compatibility and byte rules pass. It means only that the
Codex provider endpoint does not provide reliable cache-hit telemetry, so
Cambium never gates acceptance on Codex hits and never promises Codex cache
savings.

The evidence and transport notes are:

- `docs/research/cache-first-context-reuse-plan.md §12` (especially
  `:599-605`) gates measured acceptance on chat providers and says Codex is
  reported, never gated; `§13.9` (`:628`) says no Codex gates or savings
  promises.
- `src/cambium/diffundo.py:70-93` records byte-stable Codex request layout,
  sparse/non-monotonic `cached_tokens`, and rejected
  `prompt_cache_options`/`prompt_cache_breakpoint`; do not emit those fields.
- `CallResult.provider_cache_hit` is optional at `diffundo.py:260-282`, and
  `_provider_cache_hit` records only what the provider reports at `:637-648`.
  `_codex_request_body` and `_codex_usage` preserve the Codex transport at
  `:939-1007`.

### Live delegated-child compatibility nuance

A live delegated child is fork-compatible only when its spawnable spec carries
`assigned_provider` and a `fanout_config` with the epoch's matching tier/model
identity. The compatibility path is
`supervisor._pin_fork_child` (`src/cambium/supervisor.py:2328-2407`),
`supervisor._fork_cache_compatible_supervisor` (`:4545-4618`), and
`worker._fork_cache_compatible` (`src/cambium/worker.py:1987-2028`). The child
spec construction and authorization inheritance are in
`supervisor._child_spec` (`:4621-4777`).

If `assigned_provider` or the matching `fanout_config` tier/model is absent or
different, the system must emit an incompatible/skipped fork decision and use
the legacy summary-passing path with the bounded `parent_envelope`. That is
correct fail-closed behavior. Do not loosen the gate or infer provider/model
identity from a name or a cache hit. The live test proves the expected accepted
shape: `tests/scenarios/test_context_epochs.py:1574-1582` checks the child
descriptor, assigned provider, model, and `context_reuse` field.

## 8. Risks and rollback

- **Default behavior:** callers that omit `context_reuse` may now suspend at a
  successful delegate, write epoch checkpoints, fork compatible children, and
  resume. Explicitly pass false in internal callers that require the legacy
  summary path.

  parsing after removal. This is intentional: there is no replacement switch;
  the feature is always on for operator-facing commands.

  identity, redacted checkpoint, or hash mismatch into a claimed cache reuse.
- **Codex claims:** retain Codex OAuth and transport support, but never turn
  sparse/non-monotonic Codex telemetry into an acceptance gate or savings claim.

### 9.1 Accepted findings (implement)

1. **Transcript projection corrupts structured content** (HIGH).
   `_fit_transcript_to_budget` (`worker.py:1647-1672`) scales retained user
   message content by a float and slices with `_cap_utf8` — no marker, can cut
   JSON/diffs mid-token. Used by the legacy fresh path (`worker.py:3477-3483`),

   and parseable; input transcript unchanged; all three paths stay in budget.
2. **ConversationStore ghost write after reported timeout** (HIGH).
   `ConversationStore._submit` (`conversations.py:332-343`) enqueues, times
   out, raises — but never cancels; the writer commits later. The supervisor
   classifies the timeout as `conversation_store_append_failed`/fatal
   (`supervisor.py:2447-2456`, `:3642-3649`) while the row can still persist.
   Direct probe reproduced a `['ghost']` row after a reported failure.
   Fix: the operation completion contract — a timed-out append must either be
   provably not-applied (cancel/remove before raising) or the timeout must be
   reported as an indeterminate result the supervisor does not classify as an
   append failure. Regression: extend
   `test_submit_times_out_when_writer_stalls`
   (`tests/scenarios/test_conversations.py:377-402`) to release the writer,
   close/reopen, and assert `history("node") == []` (or the documented
   indeterminate contract).
3. **Warm-pool dead control contract** (MEDIUM).
   Pool is default-off everywhere real (`cli.py` `--warm-pool-size=0`,
   `run_plan`, `_Runtime`). `DEFAULT_WARM_POOL_SIZE=1` and
   `CAMBIUM_WARM_POOL_SIZE`/`_warm_pool_size()` (`supervisor.py:567-576`,
   `:731-735`) have no caller — two conflicting nominal defaults, docs claim
   "defaults to one". Fix: delete the dead helper/constant/env path (do not
   rewire a second control); correct docs; keep pool default 0. Do not delete
   the pool itself: no RSS/FD/module-global soak evidence exists either way,
   and current workers do not import DSPy (the 2.2s coldstart was
   DSPy-specific, `docs/research/worker-coldstart.md`).
4. **Cache-transition evidence tests** (MEDIUM).
   Fold placement is already cache-correct (system+schemas stay byte-identical
   before the folded message, `worker.py:1856-1860`, `:3311-3324`), but
   nothing pins it. Add tests asserting: folded message index equals the
   immutable-base length; every preceding message byte-identical across a
   fold; at most one fold per turn; character-triggered refold requires the
   full hysteresis width (high=120k, low=60k); paired provider run reports
   cached/uncached tokens and latency before/on/after folds. Widen hysteresis
   only if these measurements show material regression.
5. **IPC hardening slice** (MEDIUM, in flight).

   flood line kills the stderr task silently; `ipc._read_line` mutates
   private `reader._limit` (`ipc.py:106-118`). One canonical reader; bounded
   redacted stderr; no private-state mutation.
6. **Dynamic task data sits in the system message** (HIGH, third critique).

   generic UUIDs, so a task containing a timestamp can falsely fail.

   transcript growth preserve exact prefixes.
